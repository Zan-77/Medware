## Notes / things worth knowing while reading this

- **Legend**: `PK` primary key, `FK` foreign key, `UK` unique constraint,
  `FK_UK` a foreign key that is *also* unique (i.e. a 1:1 relation, rendered
  above with `|o--||`). Type names use `_` instead of spaces/commas
  (`decimal_12_2` = `numeric(12,2)`, `varchar_150` = `character varying(150)`)
  because Mermaid's ER attribute-type token can't contain those characters.
- `users_user` is Django's `AUTH_USER_MODEL` (`users.User`, extends
  `AbstractUser`) — it carries the framework's auth columns
  (`password`, `is_staff`, `is_superuser`, `date_joined`, …) alongside the
  project's own `role` and `is_verified`.
- `auth_group*`, `auth_permission`, `django_content_type`, `django_session`,
  `django_migrations`, `django_admin_log` are Django/`django.contrib.admin`
  framework tables, not MedWare domain tables — included for completeness
  since they exist in the live DB, but they're boilerplate.
- `users_user_groups` and `users_user_user_permissions` are Django's implicit
  M2M join tables for `User.groups` / `User.user_permissions`.
- `products_productsupplier` holds `product` + `supplier` + `discount` — it
  does **not** carry quantity/category/bill info (that lives on
  `inventory_supplierbillline`).
- `inventory_supplierbill.supplier_id` references `products_supplier`
  directly. (It previously pointed at `products_productsupplier`, which left
  `products_supplier` orphaned; corrected in migration
  `inventory/0002_alter_supplierbill_supplier`.)
- `users_user` has a **case-insensitive** partial unique index on email
  (`users_user_unique_email_ci`, on `lower(email)` where `email <> ''`)
  rather than a plain `unique=True`, because login resolves accounts with
  `email__iexact` and blank emails are allowed.

## Regenerating this file

The diagram above was produced by dumping the live schema and translating it
by hand into Mermaid. To refresh it after a migration change:

```bash
pg_dump -h 127.0.0.1 -p 5432 -U postgres -d Medware --schema-only --no-owner --no-privileges
```

then update the `erDiagram` block to match any new/changed
tables/columns/constraints.
